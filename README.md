# 答えのない問題の解決

定型でない、急に現れる答えのない問題 (上司や組織の説得、進め方がおかしい計画の見直し、業務改善) を、問題の整理、選択肢の比較、提案資料、実行計画の順に進める。Claude Code と GitHub Copilot の両方で使える。

## まず使う

```
/solve init          最初に 1 回。設定を作る
/solve ○○したい      やりたいことを文章で書くと、実行するコマンドを案内する
/solve frame <案件名>   問題を整理する (状況、関係者、論点)
```

## やりたいことから引く

| やりたいこと | 入力 |
|---|---|
| 何が問題かを整理する | `/solve frame <案件名>` |
| 選択肢を出して比べる。続けるか止めるかの判断材料を作る | `/solve options <案件名>` |
| 上司や関係部門に出す提案資料を作る | `/solve propose <案件名>` |
| 改善や試行の計画を作る | `/solve plan <案件名>` |
| 整理から資料まで通しで進める | `/solve all <案件名>` |
| 成果物どうしのつじつまを合わせる | `/solve reconcile` |
| 使ってみた学びをルールとスキルに反映する | `/solve improve` |

全部の一覧: **[逆引き辞典](.github/skills/solve/references/howto.md)**

## 誰に任せるか

| 名前 | 日本語名 | 任せること |
|---|---|---|
| orchestrator | 統括 | 窓口。迷ったらここ。担当に割り振ってまとめる |
| framer | 問題整理担当 | 状況を整理して事実と推測を分け、本当に解くべき論点を決める |
| strategist | 選択肢担当 | 選択肢を広げて評価の軸で比べ、推奨と、止める、変える、続けるの判断材料を作る |
| writer | 資料作成担当 | 決める相手に合わせて説得の筋道を組み、提案資料にする |
| planner | 実行計画担当 | 小さく試す計画、効果の測り方、やめる条件を作る |
| frame-reviewer | 前提レビュー担当 | 問題整理担当の成果物の独立レビュー |
| option-reviewer | 反論担当 | 選択肢担当の成果物の独立レビュー |
| audience-reviewer | 読み手役レビュー担当 | 資料作成担当の成果物の独立レビュー |
| reconciler | 整合担当 | 成果物どうしのつじつま合わせ、棚卸し |
| librarian | 資料管理担当 | 規定と過去の資料の登録、検索 |
| improver | 改善担当 | 使ってみた学びをルールとスキルに反映 |
